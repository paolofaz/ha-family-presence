# Family Presence v1.0.2 — Stable Release

**Context-aware family presence detection for Home Assistant.**

Family Presence brings together phone location, Bluetooth wearables, optional
backpack beacons, and physical entrance events through an event-driven
**finite-state machine (FSM)**. Each household member has a separate
**Home**, **Near Home**, or **Away** state, with a household-wide
**All Away** output for use in external Home Assistant automations.

The integration is built for everyday situations: a phone or Watch left
charging at home, a child leaving with a school backpack, intermittent
Bluetooth reception, and multiple people using a shared entrance.

## What's new in v1.0.2

**This is a release/version and documentation update only.**
The underlying presence logic is **identical to v1.0.1**. No transition
rules, source handling, configurations, entities, unique IDs, or storage
formats have been changed.

- Final stable version label updated to **v1.0.2**.
- A comprehensive, English-language [README](https://github.com/paolofaz/ha-family-presence/blob/main/README.md)
  now introduces installation, FSM behavior, configuration, examples,

- The HACS-compatible `family_presence.zip` is published under v1.0.2.

## Features

- Independent, event-driven presence FSM per household member.
- Phone geofence arrivals and departures.
- Watch Bluetooth presence with time-correlated entrance/exit evidence.
- Optional backpack BLE tracking with configurable departure hours,
  causal return eligibility, and returns outside school hours.
- The **v1.0.1 safeguard**, retained unchanged: a Watch left at home
  cannot override an accepted backpack departure even when someone else
  opens a shared door.
- Strict household All Away output: ON **only** when everyone is Away.
- Persistent states across restarts, one-shot manual Home/Away buttons,
  diagnostic status, and display-only shared entrance history.
- Home Assistant UI configuration; no YAML presence engine required.

## Reliability and safety

Family Presence **does not itself arm alarms, unlock doors, control heating,
or call actuator services**. Those actions remain in your own Home
Assistant automations. Near Home is not a confirmed Home arrival, and
a restored Away state can be stale if events were missed while Home
Assistant was offline.

The stable suite contains **226 automated tests**, with HACS validation
and Home Assistant hassfest checks.

## Installation and upgrades

Use Home Assistant Marketplace/HACS as a custom integration or download
the release's flat **`family_presence.zip`** archive.

For existing installations, update **in place**. Do not delete and
recreate the integration. Restart Home Assistant as required and check
your own alarm automations before relying on the All Away sensor.

Users of **v1.0.1** receive **no new behavior changes** in v1.0.2.
The v1.0.1 startup correction for certain older saved Near Home states
remains part of the integration.
